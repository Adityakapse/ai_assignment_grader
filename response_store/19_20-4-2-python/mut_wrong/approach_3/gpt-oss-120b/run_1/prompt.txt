QUESTION:
These tasks will again be about search trees. Reminder:
Our search trees are built from "nodes", analogous to the lecture.
A node looks like this:

class Node:
 * key
 * left
 * right
 * Parent

For this task, implement a method "delete" which deletes a
"Node" in the search tree and returns the new search tree. Use the
the method from the lecture slides, i.e. the one with "TREE-MINIMUM".
The nodes can be reused as desired. The function gets the root
of the search tree and the node to be deleted.

SAMPLE SOLUTION:
# Helper function
def tree_minimum(n):
    while n.left is not None:
        n = n.left
    return n
# Node in parameter represents root of tree
def delete(root: Node, delete: Node):
    y = None  # y: node to delete (after swap)
    if delete.left is None or delete.right is None:
        y = delete
    else:
        y = tree_minimum(delete.right)
    x = None  # non-null child of y
    if y.left is not None:
        x = y.left
    else:
        x = y.right
    # now delete y
    if x is not None:
        x.parent = y.parent
    if y.parent is None:
        root = x
    else:
        if y is y.parent.left:
            y.parent.left = x
        else:
            y.parent.right = x
    # Copy data
    if y is not delete:
        delete.key = y.key
    # y should have no reference and should be deleted by the python gc
    return root

STUDENT SOLUTION:
# Does nothing - returns the tree unchanged
def delete(root, delete):
    return root


RUBRIC:
Point 1 — Selecting y: which node to physically remove
  y is set to delete when delete has at most one child; y is set to treeMinimum(delete.right) when delete has two children.
  Buckets:
    - Wrong (0 marks): y is always set to delete regardless of how many children it has, or no selection logic is present.
    - Semi (10 marks): The case split is present but partially incorrect: for example, the condition for detecting two children is wrong, or the successor is found using the wrong subtree (e.g., treeMinimum of the left subtree instead of the right).
    - Correct (20 marks): y is correctly set to delete when delete has zero or one child, and to treeMinimum(delete.right) when delete has two children.

Point 2 — treeMinimum helper
  treeMinimum walks left from its input node until reaching a node with no left child, and returns that node.
  Buckets:
    - Wrong (0 marks): treeMinimum is absent, or always returns the input node without any traversal.
    - Semi (8 marks): treeMinimum traverses the tree but in the wrong direction (e.g., goes right instead of left), or terminates under an incorrect condition.
    - Correct (15 marks): treeMinimum walks left (n = n.left) until n.left is null and returns n, correctly finding the in-order minimum.

Point 3 — Finding x: the child of y to promote
  x is identified as y's non-null child (y.left if non-null, otherwise y.right), which may be null if y is a leaf.
  Buckets:
    - Wrong (0 marks): x is not identified; the algorithm proceeds without determining which child of y (if any) should take y's place.
    - Semi (8 marks): x is assigned but the logic is incorrect: for example, always takes y.left even when it is null, or does not handle the case where y is a leaf (x should be null).
    - Correct (15 marks): x is set to y.left when y.left is non-null, and to y.right otherwise (which may be null if y is a leaf), correctly identifying the child to promote.

Point 4 — Splicing y out of the tree
  y is removed by updating x.parent to y.parent (when x is non-null), and updating y.parent's child pointer (or root) to x.
  Buckets:
    - Wrong (0 marks): y.parent's child pointers are not updated; y remains linked in the tree after deletion.
    - Semi (10 marks): y.parent's left or right pointer is redirected to x, but x.parent is not updated (or vice versa), or the root replacement case (y.parent == null) is missing.
    - Correct (20 marks): x.parent is set to y.parent (when x is non-null); y.parent's left or right pointer is redirected to x based on which child y was; and the root replacement case (y.parent == null → root = x) is handled.

Point 5 — Copying the key when y is the successor
  When y is the in-order successor (y != delete), delete.key is updated to y.key so that the logical node is removed while the physical successor node is spliced out.
  Buckets:
    - Wrong (0 marks): The key is never copied, leaving delete.key unchanged when the successor was used; the node with delete.key remains in the tree.
    - Semi (5 marks): A key copy is attempted but without checking y != delete, potentially overwriting the key even in the direct deletion case (when y == delete).
    - Correct (10 marks): delete.key = y.key is executed only when y != delete, correctly replacing the logical node's key with the successor's key.

Point 6 — Overall correctness
  The method returns a valid BST after deletion for all cases: leaf, one child, two children, and root deletion.
  Buckets:
    - Wrong (0 marks): Method returns null or produces an invalid BST for most inputs.
    - Semi (10 marks): Deletion works for simple cases (leaf or single-child node) but fails for two-children deletion, or fails when the node to delete is the root.
    - Correct (20 marks): BST property is preserved after deletion for all cases including two-children deletion, root deletion, and leaf deletion. Correct root is returned in all cases.
